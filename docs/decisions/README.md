# CircuitMind Architecture Decisions

This directory records important architectural decisions and the reasoning behind them.

The goal is to preserve *why* a choice was made, not merely what the current code happens to do.

## Suggested format

Use sequential files such as:

```text
001-logical-vs-graphical-entities.md
002-synthetic-fixtures-independent-of-circuit-model.md
```

A decision record should normally include:

- status;
- context;
- decision;
- consequences and trade-offs;
- alternatives considered when relevant.

Decision records should be added when a choice materially constrains future architecture. Small implementation details do not need their own record.
